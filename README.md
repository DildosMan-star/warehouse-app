# ระบบคลังสินค้า (Warehouse Management System)

Next.js 14 (App Router) + Supabase (Postgres, Auth, RLS)

## ฟีเจอร์

- รับสินค้าเข้า (Stock In) / เบิกสินค้าออก (Stock Out) / โอนย้ายระหว่างตำแหน่ง / ปรับยอดสต็อก
- ดูสต็อกคงเหลือแยกตาม **คลัง → ตำแหน่งจัดเก็บ (Location) → สินค้า → จำนวน**
- จัดการสินค้า (SKU), คลัง/สาขา, ตำแหน่งจัดเก็บ
- แดชบอร์ดสรุปภาพรวม + แจ้งเตือนสินค้าใกล้ถึงจุดสั่งซื้อ
- ระบบผู้ใช้งาน 3 สิทธิ์: **admin** (ผู้ดูแลระบบ), **manager** (หัวหน้าคลัง), **staff** (พนักงาน)
- ความปลอดภัยของข้อมูลบังคับที่ชั้นฐานข้อมูลด้วย Row Level Security (RLS) ของ Supabase

## โครงสร้างสิทธิ์การใช้งาน

| สิทธิ์ | อ่านข้อมูล | รับ/เบิก/โอน/ปรับยอดสต็อก | จัดการสินค้า/คลัง/ตำแหน่ง | จัดการผู้ใช้งาน |
| --- | --- | --- | --- | --- |
| staff | ✅ | ✅ | ❌ | ❌ |
| manager | ✅ | ✅ | ✅ | ❌ |
| admin | ✅ | ✅ | ✅ | ✅ |

ผู้สมัครสมาชิก **คนแรก** ของระบบจะได้สิทธิ์ `admin` โดยอัตโนมัติ (ดูใน `supabase/schema.sql` ฟังก์ชัน `handle_new_user`)

## ขั้นตอนที่ 1 — ตั้งค่า Supabase

1. สมัคร/เข้าสู่ระบบที่ https://supabase.com แล้วกด **New Project**
   - ตั้งชื่อโปรเจกต์ เลือก Region ที่ใกล้ผู้ใช้งาน (เช่น Singapore) และตั้งรหัสผ่านฐานข้อมูล
2. เมื่อสร้างโปรเจกต์เสร็จ ไปที่เมนู **SQL Editor** (แถบด้านซ้าย)
3. กด **New query** แล้วคัดลอกเนื้อหาทั้งหมดจากไฟล์ `supabase/schema.sql` ในโปรเจกต์นี้ไปวาง
4. กด **Run** — ระบบจะสร้างตาราง, trigger, และ Row Level Security policy ให้ทั้งหมด
   - ไฟล์นี้มีข้อมูลตัวอย่าง (คลัง 2 แห่ง, ตำแหน่ง 3 ตำแหน่ง, สินค้า 3 รายการ) หากไม่ต้องการ ให้ลบส่วนท้ายของไฟล์ (หัวข้อ "ข้อมูลตัวอย่าง") ออกก่อน Run
5. ไปที่เมนู **Project Settings → API** แล้วคัดลอกค่า 2 ค่านี้เก็บไว้:
   - **Project URL**
   - **anon public key**

> เรื่องอีเมลยืนยันตัวตน: ค่าเริ่มต้นของ Supabase จะให้ผู้ใช้ยืนยันอีเมลก่อน login ได้ หากต้องการทดสอบเร็ว ๆ ให้ไปที่ **Authentication → Providers → Email** แล้วปิด "Confirm email" ชั่วคราว (แนะนำให้เปิดกลับตอนใช้งานจริง)

## ขั้นตอนที่ 2 — ตั้งค่าโปรเจกต์ในเครื่อง

```bash
# ติดตั้ง dependencies
npm install

# คัดลอกไฟล์ env แล้วใส่ค่าจากขั้นตอนที่ 1
cp .env.local.example .env.local
```

แก้ไข `.env.local`:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

```bash
# รันโปรเจกต์
npm run dev
```

เปิดเบราว์เซอร์ไปที่ http://localhost:3000 ระบบจะพาไปหน้า `/login` อัตโนมัติ

## ขั้นตอนที่ 3 — สร้างบัญชีผู้ดูแลระบบคนแรก     

1. ที่หน้า Login กด **สมัครสมาชิก**
2. กรอกชื่อ อีเมล รหัสผ่าน แล้วกดสมัคร — บัญชีนี้จะได้สิทธิ์ `admin` โดยอัตโนมัติ
3. เข้าสู่ระบบ แล้วเริ่มเพิ่มคลัง/ตำแหน่ง/สินค้าได้จากเมนูด้านซ้าย
4. ผู้ใช้งานคนถัดไปที่สมัคร จะได้สิทธิ์ `staff` เป็นค่าเริ่มต้น — ผู้ดูแลระบบสามารถเปลี่ยนสิทธิ์ได้ที่เมนู **ผู้ใช้งาน**

## โครงสร้างฐานข้อมูล (สรุป)

- `warehouses` — คลัง/สาขา
- `locations` — ตำแหน่งจัดเก็บภายในคลัง (โซน/ชั้น/บิน) อ้างอิง `warehouse_id`
- `products` — สินค้า (SKU master)
- `stock` — จำนวนคงเหลือปัจจุบัน ต่อสินค้า ต่อตำแหน่ง (อัปเดตอัตโนมัติ ห้ามเขียนตรง)
- `stock_movements` — ประวัติการเคลื่อนไหวทั้งหมด (`in` / `out` / `transfer` / `adjustment`) เป็น audit log แบบ insert-only
- `profiles` — ข้อมูลผู้ใช้งานและสิทธิ์ เชื่อมกับ `auth.users` ของ Supabase

การรับเข้า/เบิกออก/โอนย้าย/ปรับยอด ทุกครั้งจะ insert แถวใหม่ลงตาราง `stock_movements` เท่านั้น — มี trigger
(`apply_stock_movement`) คอยคำนวณและอัปเดตยอดคงเหลือในตาราง `stock` ให้อัตโนมัติ พร้อม check constraint
ป้องกันไม่ให้สต็อกติดลบ (เบิกเกินจำนวนที่มีจะถูกปฏิเสธพร้อมข้อความแจ้งเตือน)

## การ deploy

โปรเจกต์นี้ deploy บน [Vercel](https://vercel.com) ได้ทันที:

1. Push โค้ดขึ้น GitHub
2. Import โปรเจกต์เข้า Vercel
3. ใส่ Environment Variables (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`) ในหน้า Project Settings ของ Vercel
4. Deploy

## แนวทางต่อยอด

- เพิ่มระบบใบสั่งซื้อ (Purchase Order) / ใบสั่งขาย (Sales Order) เชื่อมกับ stock-in / stock-out
- เพิ่มการพิมพ์บาร์โค้ด/QR code ต่อตำแหน่งจัดเก็บและสินค้า
- Export รายงานเป็น Excel/PDF
- เพิ่ม Realtime subscription (Supabase Realtime) ให้หน้าสต็อกอัปเดตสดโดยไม่ต้อง refresh
